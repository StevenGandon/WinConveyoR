\hypertarget{md_CONTRIBUTING_autotoc_md1}{}\doxysection{\texorpdfstring{Issues}{Issues}}\label{md_CONTRIBUTING_autotoc_md1}
To work on the project you must create issues that describe what you are going~\newline
 to be be working on, and what you are planning to do on the project~\newline
 segmented in different tasks (one issue per task).~\newline
 You must follow this format to create issues \+:
\begin{DoxyItemize}
\item brief
\end{DoxyItemize}

You should also add tags to easly know what part of the project is concerned by the changes (core, cli, lib, etc.).~\newline
 You must add the issue to the Github project.~\newline
 And you should also update the state of the issue after commiting changes to track the advancement.

\hypertarget{md_CONTRIBUTING_autotoc_md3}{}\doxysection{\texorpdfstring{Branch}{Branch}}\label{md_CONTRIBUTING_autotoc_md3}
To work on the project you must work on a branch seperated of the Master/\+Main branch, if you are doing a lot of modification/addition/refactoring you must create a specific branch (if the modification are minors you may work on the {\ttfamily dev} branch) and follow the following branch name format \+:
\begin{DoxyItemize}
\item name-\/of-\/the-\/branch
\end{DoxyItemize}\hypertarget{md_CONTRIBUTING_autotoc_md4}{}\doxysubsection{\texorpdfstring{Name}{Name}}\label{md_CONTRIBUTING_autotoc_md4}
In your name you should describe as simple as possible what you\textquotesingle{}re adding to the project in your branch and what you will be working on, written in \href{https://developer.mozilla.org/en-US/docs/Glossary/Kebab_case}{\texttt{kebab-\/case}}.~\newline
 ex\+: add-\/project-\/contributor-\/documentation

\hypertarget{md_CONTRIBUTING_autotoc_md6}{}\doxysection{\texorpdfstring{Commit}{Commit}}\label{md_CONTRIBUTING_autotoc_md6}
To contribute on the project you must use this commit format to in your commit messages \+:
\begin{DoxyItemize}
\item \{PREFIX\} brief
\item \{EXTRA\+\_\+\+DESCRIPTION\}...
\end{DoxyItemize}\hypertarget{md_CONTRIBUTING_autotoc_md7}{}\doxysubsection{\texorpdfstring{Prefix}{Prefix}}\label{md_CONTRIBUTING_autotoc_md7}

\begin{DoxyItemize}
\item {\ttfamily \mbox{[}ADD\mbox{]}} \+: addition to the project (a new feature for exemple)~\newline

\item {\ttfamily \mbox{[}EDIT\mbox{]}} \+: edition/refactoring of an existing part of the code~\newline

\item {\ttfamily \mbox{[}DELETE\mbox{]}} \+: deletion of something in the project~\newline

\item {\ttfamily \mbox{[}FIX\mbox{]}} \+: bug/issue fix
\end{DoxyItemize}\hypertarget{md_CONTRIBUTING_autotoc_md8}{}\doxysubsection{\texorpdfstring{Brief}{Brief}}\label{md_CONTRIBUTING_autotoc_md8}
In your brief you should describe shortly what your prefixed actions have done.~\newline
 ex\+: \mbox{[}ADD\mbox{]} \doxylink{CONTRIBUTING_8md}{CONTRIBUTING.\+md} to the project\hypertarget{md_CONTRIBUTING_autotoc_md9}{}\doxysubsection{\texorpdfstring{Description}{Description}}\label{md_CONTRIBUTING_autotoc_md9}
You can also add a description to your commit messages by adding a new line to your commit message (in the terminal using the cli it can be done by writing git commit -\/m "{}PREFIX brief and leaving the quotes open so when you hit enter it let you write after the line break your extra description.).~\newline
 ex\+: \mbox{[}ADD\mbox{]} \doxylink{CONTRIBUTING_8md}{CONTRIBUTING.\+md} to the project~\newline
 Made the addition of a contributor documentation to let people know how to properly contribute to the project and follow the commit guidelines!

\hypertarget{md_CONTRIBUTING_autotoc_md11}{}\doxysection{\texorpdfstring{Merging}{Merging}}\label{md_CONTRIBUTING_autotoc_md11}
When you\textquotesingle{}re done programming your features on your branch you must then create a pull request on {\ttfamily dev} to merge your branch over the {\ttfamily dev} branch.~\newline
 The {\ttfamily dev} branch on release of multiple major changes should then be merge on the {\ttfamily \doxylink{namespacemain}{main}} branch also by doing a pull request to merge {\ttfamily dev} on {\ttfamily \doxylink{namespacemain}{main}}.~\newline
 In your pull request you should detail what changes you added, add reviewers and if needed apply changes according to reviews and ask the reviewers to review your pull request again.
