Lots of people download binary distributions of curl and libcurl. This document does not describe how to install curl or libcurl using such a binary package. This document describes how to compile, build and install curl and libcurl from source code.\hypertarget{md_lib_2libwconr_2build_2__deps_2curl-src_2docs_2INSTALL_autotoc_md1742}{}\doxysection{\texorpdfstring{Building using vcpkg}{Building using vcpkg}}\label{md_lib_2libwconr_2build_2__deps_2curl-src_2docs_2INSTALL_autotoc_md1742}
You can download and install curl and libcurl using the \href{https://github.com/Microsoft/vcpkg/}{\texttt{vcpkg}} dependency manager\+: \begin{DoxyVerb}git clone https://github.com/Microsoft/vcpkg.git
cd vcpkg
./bootstrap-vcpkg.sh
./vcpkg integrate install
vcpkg install curl[tool]
\end{DoxyVerb}


The curl port in vcpkg is kept up to date by Microsoft team members and community contributors. If the version is out of date, please \href{https://github.com/Microsoft/vcpkg}{\texttt{create an issue or pull request}} on the vcpkg repository.\hypertarget{md_lib_2libwconr_2build_2__deps_2curl-src_2docs_2INSTALL_autotoc_md1743}{}\doxysection{\texorpdfstring{Building from git}{Building from git}}\label{md_lib_2libwconr_2build_2__deps_2curl-src_2docs_2INSTALL_autotoc_md1743}
If you get your code off a git repository instead of a release tarball, see the {\ttfamily GIT-\/\+INFO} file in the root directory for specific instructions on how to proceed.\hypertarget{md_lib_2libwconr_2build_2__deps_2curl-src_2docs_2INSTALL_autotoc_md1744}{}\doxysection{\texorpdfstring{Unix}{Unix}}\label{md_lib_2libwconr_2build_2__deps_2curl-src_2docs_2INSTALL_autotoc_md1744}
A normal Unix installation is made in three or four steps (after you have unpacked the source archive)\+: \begin{DoxyVerb}./configure --with-openssl [--with-gnutls --with-wolfssl]
make
make test (optional)
make install
\end{DoxyVerb}


(Adjust the configure line accordingly to use the TLS library you want.)

You probably need to be root when doing the last command.

Get a full listing of all available configure options by invoking it like\+: \begin{DoxyVerb}./configure --help
\end{DoxyVerb}


If you want to install curl in a different file hierarchy than {\ttfamily /usr/local}, specify that when running configure\+: \begin{DoxyVerb}./configure --prefix=/path/to/curl/tree
\end{DoxyVerb}


If you have write permission in that directory, you can do \textquotesingle{}make install\textquotesingle{} without being root. An example of this would be to make a local install in your own home directory\+: \begin{DoxyVerb}./configure --prefix=$HOME
make
make install
\end{DoxyVerb}


The configure script always tries to find a working SSL library unless explicitly told not to. If you have Open\+SSL installed in the default search path for your compiler/linker, you do not need to do anything special. If you have Open\+SSL installed in {\ttfamily /usr/local/ssl}, you can run configure like\+: \begin{DoxyVerb}./configure --with-openssl
\end{DoxyVerb}


If you have Open\+SSL installed somewhere else (for example, {\ttfamily /opt/\+Open\+SSL}) and you have pkg-\/config installed, set the pkg-\/config path first, like this\+: \begin{DoxyVerb}env PKG_CONFIG_PATH=/opt/OpenSSL/lib/pkgconfig ./configure --with-openssl
\end{DoxyVerb}


Without pkg-\/config installed, use this\+: \begin{DoxyVerb}./configure --with-openssl=/opt/OpenSSL
\end{DoxyVerb}


If you insist on forcing a build without SSL support, even though you may have Open\+SSL installed in your system, you can run configure like this\+: \begin{DoxyVerb}./configure --without-ssl
\end{DoxyVerb}


If you have Open\+SSL installed, but with the libraries in one place and the header files somewhere else, you have to set the {\ttfamily LDFLAGS} and {\ttfamily CPPFLAGS} environment variables prior to running configure. Something like this should work\+: \begin{DoxyVerb}CPPFLAGS="-I/path/to/ssl/include" LDFLAGS="-L/path/to/ssl/lib" ./configure
\end{DoxyVerb}


If you have shared SSL libs installed in a directory where your runtime linker does not find them (which usually causes configure failures), you can provide this option to gcc to set a hard-\/coded path to the runtime linker\+: \begin{DoxyVerb}LDFLAGS=-Wl,-R/usr/local/ssl/lib ./configure --with-openssl
\end{DoxyVerb}
\hypertarget{md_lib_2libwconr_2build_2__deps_2curl-src_2docs_2INSTALL_autotoc_md1745}{}\doxysubsection{\texorpdfstring{More Options}{More Options}}\label{md_lib_2libwconr_2build_2__deps_2curl-src_2docs_2INSTALL_autotoc_md1745}
To force a static library compile, disable the shared library creation by running configure like\+: \begin{DoxyVerb}./configure --disable-shared
\end{DoxyVerb}


To tell the configure script to skip searching for thread-\/safe functions, add an option like\+: \begin{DoxyVerb}./configure --disable-thread
\end{DoxyVerb}


If you are a curl developer and use gcc, you might want to enable more debug options with the {\ttfamily -\/-\/enable-\/debug} option.

curl can be built to use a whole range of libraries to provide various useful services, and configure will try to auto-\/detect a decent default. But if you want to alter it, you can select how to deal with each individual library.\hypertarget{md_lib_2libwconr_2build_2__deps_2curl-src_2docs_2INSTALL_autotoc_md1746}{}\doxysubsection{\texorpdfstring{Select TLS backend}{Select TLS backend}}\label{md_lib_2libwconr_2build_2__deps_2curl-src_2docs_2INSTALL_autotoc_md1746}

\begin{DoxyItemize}

\item Bear\+SSL\+: {\ttfamily -\/-\/with-\/bearssl}
\item Gnu\+TLS\+: {\ttfamily -\/-\/with-\/gnutls}.

\item wolf\+SSL\+: {\ttfamily -\/-\/with-\/wolfssl}
\end{DoxyItemize}\hypertarget{md_lib_2libwconr_2build_2__deps_2curl-src_2docs_2INSTALL_autotoc_md1747}{}\doxysection{\texorpdfstring{Windows}{Windows}}\label{md_lib_2libwconr_2build_2__deps_2curl-src_2docs_2INSTALL_autotoc_md1747}

If you want to enable LDAPS support then set LDAPS=1.\hypertarget{md_lib_2libwconr_2build_2__deps_2curl-src_2docs_2INSTALL_autotoc_md1750}{}\doxysubsection{\texorpdfstring{Cygwin}{Cygwin}}\label{md_lib_2libwconr_2build_2__deps_2curl-src_2docs_2INSTALL_autotoc_md1750}
Almost identical to the Unix installation. Run the configure script in the curl source tree root with {\ttfamily sh configure}. Make sure you have the {\ttfamily sh} executable in {\ttfamily /bin/} or you will see the configure fail toward the end.

Run {\ttfamily make}\hypertarget{md_lib_2libwconr_2build_2__deps_2curl-src_2docs_2INSTALL_autotoc_md1751}{}\doxysubsection{\texorpdfstring{Disabling Specific Protocols in Windows builds}{Disabling Specific Protocols in Windows builds}}\label{md_lib_2libwconr_2build_2__deps_2curl-src_2docs_2INSTALL_autotoc_md1751}

You can use specific defines to disable specific protocols and features. See \doxysectlink{md_lib_2libwconr_2build_2__deps_2curl-src_2docs_2CURL-DISABLE}{CURL-\/\+DISABLE}{0} for the full list.

Note\+: The pre-\/processor settings can be found using the Visual Studio IDE under "{}\+Project -\/$>$ Properties -\/$>$ Configuration Properties -\/$>$ C/\+C++ -\/$>$ \+Preprocessor"{}.\hypertarget{md_lib_2libwconr_2build_2__deps_2curl-src_2docs_2INSTALL_autotoc_md1752}{}\doxysubsection{\texorpdfstring{Using BSD-\/style lw\+IP instead of Winsock TCP/\+IP stack in Win32 builds}{Using BSD-\/style lw\+IP instead of Winsock TCP/\+IP stack in Win32 builds}}\label{md_lib_2libwconr_2build_2__deps_2curl-src_2docs_2INSTALL_autotoc_md1752}
In order to compile libcurl and curl using BSD-\/style lw\+IP TCP/\+IP stack it is necessary to make the definition of the preprocessor symbol {\ttfamily USE\+\_\+\+LWIPSOCK} visible to libcurl and curl compilation processes. To set this definition you have the following alternatives\+:

\item Modify the "{}\+Preprocessor Definitions"{} in the libcurl project
\end{DoxyItemize}

Once that libcurl has been built with BSD-\/style lw\+IP TCP/\+IP stack support, in order to use it with your program it is mandatory that your program includes lw\+IP header file {\ttfamily \texorpdfstring{$<$}{<}lwip/opt.\+h\texorpdfstring{$>$}{>}} (or another lw\+IP header that includes this) before including any libcurl header. Your program does not need the {\ttfamily USE\+\_\+\+LWIPSOCK} preprocessor definition which is for libcurl internals only.

Compilation has been verified with lw\+IP 1.\+4.\+0.

This BSD-\/style lw\+IP TCP/\+IP stack support must be considered experimental given that it has been verified that lw\+IP 1.\+4.\+0 still needs some polish, and libcurl might yet need some additional adjustment.\hypertarget{md_lib_2libwconr_2build_2__deps_2curl-src_2docs_2INSTALL_autotoc_md1753}{}\doxysubsection{\texorpdfstring{Important static libcurl usage note}{Important static libcurl usage note}}\label{md_lib_2libwconr_2build_2__deps_2curl-src_2docs_2INSTALL_autotoc_md1753}
When building an application that uses the static libcurl library on Windows, you must add {\ttfamily -\/DCURL\+\_\+\+STATICLIB} to your {\ttfamily CFLAGS}. Otherwise the linker will look for dynamic import symbols.\hypertarget{md_lib_2libwconr_2build_2__deps_2curl-src_2docs_2INSTALL_autotoc_md1754}{}\doxysubsection{\texorpdfstring{Legacy Windows and SSL}{Legacy Windows and SSL}}\label{md_lib_2libwconr_2build_2__deps_2curl-src_2docs_2INSTALL_autotoc_md1754}
Schannel (from Windows SSPI), is the native SSL library in Windows. If you will be using curl in one of those earlier versions of Windows you should choose another SSL backend such as Open\+SSL.\hypertarget{md_lib_2libwconr_2build_2__deps_2curl-src_2docs_2INSTALL_autotoc_md1755}{}\doxysection{\texorpdfstring{Apple Platforms (mac\+OS, i\+OS, tv\+OS, watch\+OS, and their simulator counterparts)}{Apple Platforms (mac\+OS, i\+OS, tv\+OS, watch\+OS, and their simulator counterparts)}}\label{md_lib_2libwconr_2build_2__deps_2curl-src_2docs_2INSTALL_autotoc_md1755}
On modern Apple operating systems, curl can be built to use Apple\textquotesingle{}s SSL/\+TLS implementation, Secure Transport, instead of Open\+SSL. To build with Secure Transport for SSL/\+TLS, use the configure option {\ttfamily -\/-\/with-\/secure-\/transport}.

When Secure Transport is in use, the curl options {\ttfamily -\/-\/cacert} and {\ttfamily -\/-\/capath} and their libcurl equivalents, will be ignored, because Secure Transport uses the certificates stored in the Keychain to evaluate whether or not to trust the server. This, of course, includes the root certificates that ship with the OS. The {\ttfamily -\/-\/cert} and {\ttfamily -\/-\/engine} options, and their libcurl equivalents, are currently unimplemented in curl with Secure Transport.

In general, a curl build for an Apple {\ttfamily ARCH/\+SDK/\+DEPLOYMENT\+\_\+\+TARGET} combination can be taken by providing appropriate values for {\ttfamily ARCH}, {\ttfamily SDK}, {\ttfamily DEPLOYMENT\+\_\+\+TARGET} below and running the commands\+:


\begin{DoxyCode}{0}
\DoxyCodeLine{\#\ Set\ these\ three\ according\ to\ your\ needs}
\DoxyCodeLine{export\ ARCH=x86\_64}
\DoxyCodeLine{export\ SDK=macosx}
\DoxyCodeLine{export\ DEPLOYMENT\_TARGET=10.8}
\DoxyCodeLine{}
\DoxyCodeLine{export\ CFLAGS="{}-\/arch\ \$ARCH\ -\/isysroot\ \$(xcrun\ -\/sdk\ \$SDK\ -\/-\/show-\/sdk-\/path)\ -\/m\$SDK-\/version-\/min=\$DEPLOYMENT\_TARGET"{}}
\DoxyCodeLine{./configure\ -\/-\/host=\$ARCH-\/apple-\/darwin\ -\/-\/prefix\ \$(pwd)/artifacts\ -\/-\/with-\/secure-\/transport}
\DoxyCodeLine{make\ -\/j8}

For IBM i (formerly OS/400), you can use curl in two different ways\+:


\begin{DoxyItemize}
\item Natively, running in the {\bfseries{ILE}}. The obvious use is being able to call curl from ILE C or RPG applications.
\begin{DoxyItemize}
\item You will need to build this from source. See {\ttfamily packages/\+OS400/\+README} for the ILE specific build instructions.
\end{DoxyItemize}
\item In the {\bfseries{PASE}} environment, which runs AIX programs. curl will be built as it would be on AIX.
\begin{DoxyItemize}
\item IBM provides builds of curl in their Yum repository for PASE software.
\item To build from source, follow the Unix instructions.
\end{DoxyItemize}
\end{DoxyItemize}

There are some additional limitations and quirks with curl on this platform; they affect both environments.\hypertarget{md_lib_2libwconr_2build_2__deps_2curl-src_2docs_2INSTALL_autotoc_md1758}{}\doxysubsection{\texorpdfstring{Multi-\/threading notes}{Multi-\/threading notes}}\label{md_lib_2libwconr_2build_2__deps_2curl-src_2docs_2INSTALL_autotoc_md1758}
By default, jobs in IBM i will not start with threading enabled. (Exceptions include interactive PASE sessions started by {\ttfamily QP2\+TERM} or SSH.) If you use curl in an environment without threading when options like asynchronous DNS were enabled, you will get messages like\+:


\begin{DoxyCode}{0}
\DoxyCodeLine{getaddrinfo()\ thread\ failed\ to\ start}

\end{DoxyCode}


Do not panic. curl and your program are not broken. You can fix this by\+:


\begin{DoxyItemize}
\item Set the environment variable {\ttfamily QIBM\+\_\+\+MULTI\+\_\+\+THREADED} to {\ttfamily Y} before starting your program. This can be done at whatever scope you feel is appropriate.
\item Alternatively, start the job with the {\ttfamily ALWMLTTHD} parameter set to {\ttfamily \texorpdfstring{$\ast$}{*}\+YES}.

There are a number of configure options that can be used to reduce the size of libcurl for embedded applications where binary size is an important factor. First, be sure to set the {\ttfamily CFLAGS} variable when configuring with any relevant compiler optimization flags to reduce the size of the binary. For gcc, this would mean at minimum the -\/Os option, and potentially the {\ttfamily -\/march=X}, {\ttfamily -\/mdynamic-\/no-\/pic} and {\ttfamily -\/flto} options as well, e.\+g. \begin{DoxyVerb}./configure CFLAGS='-Os' LDFLAGS='-Wl,-Bsymbolic'...
\end{DoxyVerb}


Note that newer compilers often produce smaller code than older versions due to improved optimization.

Be sure to specify as many {\ttfamily -\/-\/disable-\/} and {\ttfamily -\/-\/without-\/} flags on the configure command-\/line as you can to disable all the libcurl features that you know your application is not going to need. The GNU compiler and linker have a number of options that can reduce the size of the libcurl dynamic libraries on some platforms even further. Specify them by providing appropriate {\ttfamily CFLAGS} and {\ttfamily LDFLAGS} variables on the configure command-\/line, e.\+g. \begin{DoxyVerb}CFLAGS="-Os -ffunction-sections -fdata-sections
        -fno-unwind-tables -fno-asynchronous-unwind-tables -flto"
LDFLAGS="-Wl,-s -Wl,-Bsymbolic -Wl,--gc-sections"
\end{DoxyVerb}


Be sure also to strip debugging symbols from your binaries after compiling using \textquotesingle{}strip\textquotesingle{} (or the appropriate variant if cross-\/compiling). If space is really tight, you may be able to remove some unneeded sections of the shared library using the -\/R option to objcopy (e.\+g. the .comment section).

Using these techniques it is possible to create a basic HTTP-\/only libcurl shared library for i386 Linux platforms that is only 133 KiB in size (as of libcurl version 7.\+80.\+0, using gcc 11.\+2.\+0).

You may find that statically linking libcurl to your application will result in a lower total size than dynamically linking.
