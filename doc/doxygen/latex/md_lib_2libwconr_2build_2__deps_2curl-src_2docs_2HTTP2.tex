libcurl uses this 3rd party library for the low level protocol handling parts. The reason for this is that HTTP/2 is much more complex at that layer than HTTP/1.\+1 (which we implement on our own) and that nghttp2 is an already existing and well functional library.

We require at least version 1.\+12.\+0.\hypertarget{md_lib_2libwconr_2build_2__deps_2curl-src_2docs_2HTTP2_autotoc_md1706}{}\doxysection{\texorpdfstring{Over an \href{http://}{\texttt{http\+://}} URL}{Over an \href{http://}{\texttt{http\+://}} URL}}\label{md_lib_2libwconr_2build_2__deps_2curl-src_2docs_2HTTP2_autotoc_md1706}
If {\ttfamily CURLOPT\+\_\+\+HTTP\+\_\+\+VERSION} is set to {\ttfamily \doxylink{curl_8h_a7c416db649a9cbd5a27c692e8e4a7b7cad7d493f095b039283d9e0c6332d8b622}{CURL\+\_\+\+HTTP\+\_\+\+VERSION\+\_\+2\+\_\+0}}, libcurl will include an upgrade header in the initial request to the host to allow upgrading to HTTP/2.

Possibly we can later introduce an option that will cause libcurl to fail if not possible to upgrade. Possibly we introduce an option that makes libcurl use HTTP/2 at once over \href{http://}{\texttt{http\+://}}\hypertarget{md_lib_2libwconr_2build_2__deps_2curl-src_2docs_2HTTP2_autotoc_md1707}{}\doxysection{\texorpdfstring{Over an \href{https://}{\texttt{https\+://}} URL}{Over an \href{https://}{\texttt{https\+://}} URL}}\label{md_lib_2libwconr_2build_2__deps_2curl-src_2docs_2HTTP2_autotoc_md1707}
If {\ttfamily CURLOPT\+\_\+\+HTTP\+\_\+\+VERSION} is set to {\ttfamily \doxylink{curl_8h_a7c416db649a9cbd5a27c692e8e4a7b7cad7d493f095b039283d9e0c6332d8b622}{CURL\+\_\+\+HTTP\+\_\+\+VERSION\+\_\+2\+\_\+0}}, libcurl will use ALPN to negotiate which protocol to continue with. Possibly introduce an option that will cause libcurl to fail if not possible to use HTTP/2.

{\ttfamily \doxylink{curl_8h_a7c416db649a9cbd5a27c692e8e4a7b7ca153a446054f34c6bcbca7a690209f284}{CURL\+\_\+\+HTTP\+\_\+\+VERSION\+\_\+2\+TLS}} was added in 7.\+47.\+0 as a way to ask libcurl to prefer HTTP/2 for HTTPS but stick to 1.\+1 by default for plain old \doxylink{structHTTP}{HTTP} connections.

ALPN is the TLS extension that HTTP/2 is expected to use.

{\ttfamily CURLOPT\+\_\+\+SSL\+\_\+\+ENABLE\+\_\+\+ALPN} is offered to allow applications to explicitly disable ALPN.\hypertarget{md_lib_2libwconr_2build_2__deps_2curl-src_2docs_2HTTP2_autotoc_md1708}{}\doxysection{\texorpdfstring{Multiplexing}{Multiplexing}}\label{md_lib_2libwconr_2build_2__deps_2curl-src_2docs_2HTTP2_autotoc_md1708}
Starting in 7.\+43.\+0, libcurl fully supports HTTP/2 multiplexing, which is the term for doing multiple independent transfers over the same physical TCP connection.

To take advantage of multiplexing, you need to use the multi interface and set {\ttfamily CURLMOPT\+\_\+\+PIPELINING} to {\ttfamily \doxylink{http2-upload_8c_af29d172b038fadd90daf541df3b945c6}{CURLPIPE\+\_\+\+MULTIPLEX}}. With that bit set, libcurl will attempt to re-\/use existing HTTP/2 connections and just add a new stream over that when doing subsequent parallel requests.

While libcurl sets up a connection to an \doxylink{structHTTP}{HTTP} server there is a period during which it does not know if it can pipeline or do multiplexing and if you add new transfers in that period, libcurl will default to start new connections for those transfers. With the new option {\ttfamily CURLOPT\+\_\+\+PIPEWAIT} (added in 7.\+43.\+0), you can ask that a transfer should rather wait and see in case there\textquotesingle{}s a connection for the same host in progress that might end up being possible to multiplex on. It favors keeping the number of connections low to the cost of slightly longer time to first byte transferred.\hypertarget{md_lib_2libwconr_2build_2__deps_2curl-src_2docs_2HTTP2_autotoc_md1709}{}\doxysection{\texorpdfstring{Applications}{Applications}}\label{md_lib_2libwconr_2build_2__deps_2curl-src_2docs_2HTTP2_autotoc_md1709}
We hide HTTP/2\textquotesingle{}s binary nature and convert received HTTP/2 traffic to headers in \doxylink{structHTTP}{HTTP} 1.\+1 style. This allows applications to work unmodified.\hypertarget{md_lib_2libwconr_2build_2__deps_2curl-src_2docs_2HTTP2_autotoc_md1710}{}\doxysection{\texorpdfstring{curl tool}{curl tool}}\label{md_lib_2libwconr_2build_2__deps_2curl-src_2docs_2HTTP2_autotoc_md1710}
curl offers the {\ttfamily -\/-\/http2} command line option to enable use of HTTP/2.

curl offers the {\ttfamily -\/-\/http2-\/prior-\/knowledge} command line option to enable use of HTTP/2 without HTTP/1.\+1 Upgrade.

Since 7.\+47.\+0, the curl tool enables HTTP/2 by default for HTTPS connections.\hypertarget{md_lib_2libwconr_2build_2__deps_2curl-src_2docs_2HTTP2_autotoc_md1711}{}\doxysection{\texorpdfstring{curl tool limitations}{curl tool limitations}}\label{md_lib_2libwconr_2build_2__deps_2curl-src_2docs_2HTTP2_autotoc_md1711}
The command line tool does not support HTTP/2 server push. It supports multiplexing when the parallel transfer option is used.\hypertarget{md_lib_2libwconr_2build_2__deps_2curl-src_2docs_2HTTP2_autotoc_md1712}{}\doxysection{\texorpdfstring{HTTP Alternative Services}{HTTP Alternative Services}}\label{md_lib_2libwconr_2build_2__deps_2curl-src_2docs_2HTTP2_autotoc_md1712}
Alt-\/\+Svc is an extension with a corresponding frame (ALTSVC) in HTTP/2 that tells the client about an alternative "{}route"{} to the same content for the same origin server that you get the response from. A browser or long-\/living client can use that hint to create a new connection asynchronously. For libcurl, we may introduce a way to bring such clues to the application and/or let a subsequent request use the alternate route automatically.
