We write curl and libcurl to compile with C89 compilers. On 32-\/bit and up machines. Most of libcurl assumes more or less POSIX compliance but that is not a requirement.

We write libcurl to build and work with lots of third party tools, and we want it to remain functional and buildable with these and later versions (older versions may still work but is not what we work hard to maintain)\+:\hypertarget{md_lib_2libwconr_2build_2__deps_2curl-src_2docs_2INTERNALS_autotoc_md1766}{}\doxysection{\texorpdfstring{Dependencies}{Dependencies}}\label{md_lib_2libwconr_2build_2__deps_2curl-src_2docs_2INTERNALS_autotoc_md1766}

All symbols used internally in libcurl must use a {\ttfamily Curl\+\_\+} prefix if they are used in more than a single file. Single-\/file symbols must be made static. Public ("{}exported"{}) symbols must use a {\ttfamily curl\+\_\+} prefix. Public API functions are marked with {\ttfamily \doxylink{curl_8h_a3adb15f21a822fbf7e879d3b78474490}{CURL\+\_\+\+EXTERN}} in the public header files so that all others can be hidden on platforms where this is possible.
