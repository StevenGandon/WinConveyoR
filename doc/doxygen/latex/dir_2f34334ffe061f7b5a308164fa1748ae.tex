 \href{https://github.com/zhangyuang/node-ffi-rs/actions}{\texttt{}} \hypertarget{dir_2f34334ffe061f7b5a308164fa1748ae_autotoc_md166}{}\doxysubsection{\texorpdfstring{Description}{Description}}\label{dir_2f34334ffe061f7b5a308164fa1748ae_autotoc_md166}
\href{https://github.com/zhangyuang/node-ffi-rs}{\texttt{ffi-\/rs}} is a high-\/performance module written in Rust and N-\/\+API that provides FFI (Foreign Function Interface) features for Node.\+js. It allows developers to call functions written in other languages such as C++, C, and Rust directly from Java\+Script without writing any C++ code.

This module aims to provide similar functionality to the node-\/ffi module but with a completely rewritten underlying codebase. The node-\/ffi module has been unmaintained for several years and is no longer usable, so ffi-\/rs was developed to fill that void.\hypertarget{dir_2f34334ffe061f7b5a308164fa1748ae_autotoc_md167}{}\doxysubsection{\texorpdfstring{Features}{Features}}\label{dir_2f34334ffe061f7b5a308164fa1748ae_autotoc_md167}

\begin{DoxyItemize}
\item High performance ✨
\item Better type hints 🧐
\item Simpler data description and API interface 💗
\item Support more different data types between {\ttfamily Node.\+js} and {\ttfamily C} 😊
\item Support modifying data in place 🥸
\item Provide many ways to handle pointer type directly 🐮
\item Support running ffi task in a new thread 🤩️
\item Support output errno info 🤔️
\item No need to use \href{https://www.npmjs.com/package/ref}{\texttt{ref}} to handle pointer 🤫

There are two types of arrays in C language like {\ttfamily int\texorpdfstring{$\ast$}{*} array} and {\ttfamily int array\mbox{[}100\mbox{]}} that have some different usages.

The first type {\ttfamily int\texorpdfstring{$\ast$}{*} array} is a pointer type storing the first address of the array.

The second type {\ttfamily int array\mbox{[}100\mbox{]}} is a fixed-\/length array and each element in the array has a continuous address.

If you use an array as a function parameter, this usually passes an array pointer regardless of which type you define. But if the array type is defined in a struct, the two types of array definitions will cause different sizes and alignments of the struct.

So, {\ttfamily ffi-\/rs} needs to distinguish between the two types.

\hypertarget{dir_2f34334ffe061f7b5a308164fa1748ae_autotoc_md199}{}\doxysubsection{\texorpdfstring{Memory Management}{Memory Management}}\label{dir_2f34334ffe061f7b5a308164fa1748ae_autotoc_md199}
It\textquotesingle{}s important to free the memory allocations during a single ffi call to prevent memory leaks.

What kinds of data memory are allocated in this?


\begin{DoxyItemize}
\item Call parameters in the Rust environment which are allocated in the heap like {\ttfamily String}
\item Return value which in the C environment which are allocated in the heap like {\ttfamily char\texorpdfstring{$\ast$}{*}}
\end{DoxyItemize}

By default, {\ttfamily ffi-\/rs} will free call parameters memory which are allocated in Rust.

But it will not free the return value from the C side since some C dynamic libraries will manage their memory automatically (when ffi-\/rs \texorpdfstring{$>$}{>}= 1.\+0.\+79)

There are two ways to prevent {\ttfamily ffi-\/rs} from releasing memory\+:


\begin{DoxyItemize}
\item Set {\ttfamily free\+Result\+Memory\+: false} when calling {\ttfamily load} method, the default value is false
\end{DoxyItemize}

If you set free\+Result\+Memory to false, {\ttfamily ffi-\/rs} will not release the return result memory which was allocated in the C environment


\begin{DoxyItemize}
\item Use {\ttfamily Data\+Type.\+External} as params\+Type or ret\+Type
\end{DoxyItemize}

If developers use {\ttfamily Data\+Type.\+External} as params\+Type or ret\+Type, please use {\ttfamily free\+Pointer} to release the memory of the pointer when this memory is no longer in use. ref \href{./test.ts\#170}{\texttt{test.\+ts}}\hypertarget{dir_2f34334ffe061f7b5a308164fa1748ae_autotoc_md200}{}\doxysubsection{\texorpdfstring{run\+In\+New\+Thread}{run\+In\+New\+Thread}}\label{dir_2f34334ffe061f7b5a308164fa1748ae_autotoc_md200}
