This document describes how to compile, build and install curl and libcurl from sources using the Visual C++ build tool. To build with VC++, you will of course have to first install VC++. The minimum required version of VC is 6 (part of Visual Studio 6). However using a more recent version is strongly recommended.

VC++ is also part of the Windows Platform SDK. You do not have to install the full Visual Studio or Visual C++ if all you want is to build curl.

The latest Platform SDK can be downloaded freely from \mbox{[}Windows SDK and emulator archive\mbox{]}(\href{https://developer.microsoft.com/en-us/windows/downloads/sdk-archive}{\texttt{https\+://developer.\+microsoft.\+com/en-\/us/windows/downloads/sdk-\/archive}})\hypertarget{dir_6ae10eac73b26a5718de68eba8ea3be8_autotoc_md1942}{}\doxysubsubsection{\texorpdfstring{Prerequisites}{Prerequisites}}\label{dir_6ae10eac73b26a5718de68eba8ea3be8_autotoc_md1942}

If you are using mode=static nmake will create and link to the static build of libcurl but {\itshape not} the static CRT. If you must you can force nmake to link in the static CRT by passing {\ttfamily RTLIBCFG=static}. Typically you shouldn\textquotesingle{}t use that option, and nmake will default to the DLL CRT. {\ttfamily RTLIBCFG} is rarely used and therefore rarely tested. When passing {\ttfamily RTLIBCFG} for a configuration that was already built but not with that option, or if the option was specified differently, you must destroy the build directory containing the configuration so that nmake can build it from scratch.

This option is not recommended unless you have enough development experience to know how to match the runtime library for linking (that is, the CRT). When building an application that uses the static libcurl library on Windows, you must define {\ttfamily \doxylink{config-plan9_8h_aa07d4a99236e09c992abe5789d975472}{CURL\+\_\+\+STATICLIB}}. Otherwise the linker will look for dynamic import symbols.

The static library name has an {\ttfamily \+\_\+a} suffix in the basename and the debug library name has a {\ttfamily \+\_\+debug} suffix in the basename. For example, {\ttfamily libcurl\+\_\+a\+\_\+debug.\+lib} is a static debug build of libcurl.

You may need a separate build of libcurl for each VC configuration combination (for example\+: Debug\texorpdfstring{$\vert$}{|}\+Win32, Debug\texorpdfstring{$\vert$}{|}x64, Release\texorpdfstring{$\vert$}{|}\+Win32, Release\texorpdfstring{$\vert$}{|}x64).

You must specify any additional dependencies needed by your build of static libcurl (for example\+: {\ttfamily advapi32.\+lib;crypt32.\+lib;normaliz.\+lib;ws2\+\_\+32.\+lib;wldap32.\+lib}).\hypertarget{dir_6ae10eac73b26a5718de68eba8ea3be8_autotoc_md1949}{}\doxysubsubsection{\texorpdfstring{Legacy Windows and SSL}{Legacy Windows and SSL}}\label{dir_6ae10eac73b26a5718de68eba8ea3be8_autotoc_md1949}
When you build curl using the build files in this directory the default SSL backend will be Schannel (Windows SSPI), the native SSL library that comes with the Windows OS. Schannel in Windows \texorpdfstring{$<$}{<}= XP is not able to connect to servers that no longer support the legacy handshakes and algorithms used by those versions. If you will be using curl in one of those earlier versions of Windows you should choose another SSL backend like Open\+SSL.
