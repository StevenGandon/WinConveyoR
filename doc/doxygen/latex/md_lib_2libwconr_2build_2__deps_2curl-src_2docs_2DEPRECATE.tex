If any of these deprecated features is a cause for concern for you, please email the \href{https://lists.haxx.se/listinfo/curl-library}{\texttt{curl-\/library mailing list}} as soon as possible and explain to us why this is a problem for you and how your use case cannot be satisfied properly using a workaround.\hypertarget{md_lib_2libwconr_2build_2__deps_2curl-src_2docs_2DEPRECATE_autotoc_md1586}{}\doxysection{\texorpdfstring{Support for systems without 64 bit data types}{Support for systems without 64 bit data types}}\label{md_lib_2libwconr_2build_2__deps_2curl-src_2docs_2DEPRECATE_autotoc_md1586}
curl will {\itshape require} support for a 64 bit data type (like {\ttfamily long long} or an alternative) to build. These days, few systems are used where no such type is around so the cost of maintaining this support is increasingly unnecessary to spent effort and time on, while supporting 32 bit values for some of those fields is complicated and hard to test.

Adding this requirement will make the code simpler, easier to maintain and the test coverage better. It is a low price too, since virtually no users are still building curl on such systems.

{\ttfamily long long} was not a standard type until C99, but has been supported by C89 compilers since the 1990s.

Starting in 8.\+0.\+0 (March 2023), the plan is to drop support.

Starting in 7.\+86.\+0, building curl with configure requires the additional flag {\ttfamily -\/-\/with-\/n64-\/deprecated} if the {\ttfamily \doxylink{system_8h_a494e2b4279dc064f7ed1d0abd602b28d}{curl\+\_\+off\+\_\+t}} type on your system is smaller than 8 bytes, in an attempt to highlight these plans to affected users.\hypertarget{md_lib_2libwconr_2build_2__deps_2curl-src_2docs_2DEPRECATE_autotoc_md1587}{}\doxysection{\texorpdfstring{NSS}{NSS}}\label{md_lib_2libwconr_2build_2__deps_2curl-src_2docs_2DEPRECATE_autotoc_md1587}
We remove support for building curl with the NSS TLS library in August 2023.


\begin{DoxyItemize}
\item There are few users left who use curl+\+NSS
\item NSS has few users outside of curl as well (primarily Firefox)
\item NSS is harder than ever to find documentation for
\item NSS was always "{}best"{} used with Red Hat Linux when they provided additional features on top of the regular NSS that is not shipped by the vanilla library
\end{DoxyItemize}

Starting in 7.\+82.\+0, building curl to use NSS configure requires the additional flag {\ttfamily -\/-\/with-\/nss-\/deprecated} in an attempt to highlight these plans.\hypertarget{md_lib_2libwconr_2build_2__deps_2curl-src_2docs_2DEPRECATE_autotoc_md1588}{}\doxysection{\texorpdfstring{past removals}{past removals}}\label{md_lib_2libwconr_2build_2__deps_2curl-src_2docs_2DEPRECATE_autotoc_md1588}
